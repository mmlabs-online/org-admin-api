### Deviations
- Production size: about +622 / -124 lines (app + migration), above the plan's ~470 estimate; the growth is the explicit per-mutator `try/except` blocks (formatted one argument per line) and the shared `_build` helper.
- `RequestIdMiddleware` stores the CIDR strings and calls `peer_is_trusted` per request (it parses the networks each time) instead of parsing them once, so one helper serves both `client_ip()` and the middleware. The behaviour is the same.
- `record_failure` raises `ValueError` for `outcome=SUCCESS` before its `try` (the plan says "asserts"; ruff `S101` forbids `assert` in `app/`).
- Logout: `auth.logged_out` / `auth.logged_out_all` carry `app_key` (the calling app). The plan's logout bullet does not name `app_key`, but §10 says to pass `_app.key` wherever `AppContextDep` exists.
- `POST /auth/apps/{key}/join` is classified as audited (`app.joined`, since ADM-004) in the identity coverage sets. The plan lists only signup, token, resend and forgot as not audited.

### Follow-ups (noticed, not done)
- `audit_log.occurred_at` is `now()` (transaction start): in tests every row of one test shares it, so tests that check order must not rely on `occurred_at`. In production, a failure row's timestamp is the start of its own transaction after the rollback. No change needed; noted for reviewers.
- `peer_is_trusted` could take pre-parsed networks if per-request parsing ever shows up in profiles.
- From the plan: `auth.signed_up`; audit reads of the audit log; the runtime DB role split; an alert on failure/denied volume; a request id derived from `CF-Ray`; read-time IP masking before `admin:audit:read` is widened; an admin rate limiter; ADM-004c retention purge.
