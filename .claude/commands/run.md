You are the **orchestrator** for ticket `$ARGUMENTS`. Read `.claude/loop.config.md` first. A setting missing from
that file takes the default named in this command. For several tickets at once, use `/run-batch`.

**Models.** Each agent runs on the `model:` in its file, unless **Model overrides** in `loop.config.md` names it
(pass that model in the Agent call). An override beats the Cost controls below (no downgrade for an overridden
agent). This orchestrator does bookkeeping only: a session started on sonnet is enough (`claude --model sonnet`).
**Usage.** For every Agent call, note the agent, the model and the token usage the call reports; the Handoff entry
records them.

**Board rule:** `work/backlog.md` is the shared board and is changed **only on `main`** (commit `chore: board — …`, pull first, push). Ticket branches change only their own `work/tickets/<ID>/` files (plus `work/ming-todo.md` when a stop adds an item), so parallel PRs never conflict on the board. The ticket's own `ticket.md` is the source of truth for its state; the board mirrors it.
You dispatch subagents and keep the board true. You write **no product code, no plan, no review** yourself — only ticket state, backlog rows, consult files, review-agent files, Handoff entries and the escalation report.

## 0. Select and prepare
1. `git switch main && git pull --ff-only`. Refresh the board first: for every ticket whose `ticket.md` on its branch or on `main` has a PR link, check it (`gh pr view <url> --json state,mergedAt`, or the GitHub MCP); if merged, set `MERGED` in the board row (and in `ticket.md` on `main` if it was merged with `DONE`). Also mirror the current state of open tickets from their branches into the board. Commit `chore: board — sync` on `main` and push if anything changed.
2. If `$ARGUMENTS` is empty, pick the first runnable `BUG-xxx` with `Severity: S1`; otherwise the first runnable row in **pick order** (`loop.config.md` → Selection; default `board` = `work/backlog.md`
   row order; `priority` = P0 > P1 > P2 > P3, then row order):
   - state `BACKLOG`, or `BLOCKED` whose blocking questions / plan approval are now answered in ticket.md (*Notes / answers from Ming*);
   - every ticket in its `Depends on` is `MERGED` (a dependency in another repo, written `<repo> <ID>`, is met only when that ticket is `MERGED` or `DONE` with a merged PR on that repo's `main`; if you cannot reach the repo, treat it as unmet and say so);
   - every `M-n` in its `Needs Ming` is ticked (`- [x]`) in `work/ming-todo.md`;
   - `Claimed by` is empty, or older than 12 hours (a stale claim — say so in the report).
   If none is runnable, report "Nothing runnable" with the reason for the next three rows (waiting on merge of X / Ming item M-n / blocked) and stop.
3. With an explicit ID, check the same conditions; if one fails, stop and tell Ming which one. Refuse `DONE`, `MERGED` or `ESCALATED` tickets.
4. Make sure the working tree is clean (`git status --porcelain`). If not, stop and report.
5. Create or switch to branch `ticket/<ID>` from the latest `origin/main`. If the environment mandates a different working branch (e.g. a cloud session's designated branch), use that branch instead and say so in the report.
6. Run the **Prepare** step of `loop.config.md` (dependency install, local database…) so checks can run.
7. In ticket.md set `Claimed by: claude@<ISO timestamp>` and state `PLANNING`. Also set the board row to `PLANNING` on `main` (board rule) before switching to the ticket branch. Commit `work/` (`<ID>: start planning`) and push the branch, so another agent sees the claim.

## Bug tickets (`BUG-xxx`, `Type: bug`)
Same loop, plus: the planner's first test is a **regression test** that reproduces the bug (at the test level `loop.config.md` names for bugs; when that level cannot see the bug — CSS, CSP, real browser APIs, infrastructure — add a one-off scripted check recorded in impl-log); the implementer writes it first and records in impl-log that it failed before the fix; the reviewer gives REWORK without that evidence. S1 bugs are picked before other runnable tickets.

## 1. Consult (only for the ticket's `Areas`)
Use the **Consult** table in `loop.config.md` (area → specialist agent), with **Cost controls**:
- **Fast lane** (default `on`): a ticket of Size `XS` or `S` whose Gate is `none` skips this step.
  Unless an override says otherwise, its planner runs on `sonnet`.
- **Max consultants** (default `2`, `0` = no limit): dispatch at most that many, in the order of the ticket's `Areas`.

Dispatch the matching specialists **in parallel** (one message, several Agent calls), each with: the ticket path, "consult mode, read-only, return Findings / Recommendations / Risks / Open questions". Save each reply verbatim to `work/tickets/<ID>/consult-<agent>.md`. Skip this step if `Areas` matches no row, or if this is a resumed `BLOCKED` ticket that already has consult files.

## 2. Plan
Dispatch `planner` (model: override, else `sonnet` on the fast lane, else its default) with the ticket path (on a resumed ticket: "re-plan using the answers in ticket.md"). When it returns, read `plan.md`:
- `Status: BLOCKED` → set state `BLOCKED`, go to **Stop and hand off** (below) with the blocking questions.
- `Status: READY` and ticket field `Gate` is `plan-approval` and *Notes / answers from Ming* has no "Plan approved" line dated after the plan → set state `BLOCKED`, add the line `Waiting for Ming: plan approval (High tier)` to ticket.md, add an unticked item to `work/ming-todo.md` ("Approve plan for <ID>: work/tickets/<ID>/plan.md"), go to **Stop and hand off**.
- `Status: READY` otherwise → set state `IN_PROGRESS`, commit `work/` (`<ID>: plan`), continue.

Which tickets get `Gate: plan-approval` is set by **Plan approval gate** in `loop.config.md` (always: tickets touching a **High path**, mirrored in `.github/risk-tiers.yml`; optionally also every `P1` ticket). If the plan's file list touches a High path, or the policy covers the ticket's priority, and the ticket's Gate is `none`, set `Gate: plan-approval` and treat it as above.

## 3. Implement
Dispatch `implementer` with: ticket path, "implement plan.md; attempt N". Verify impl-log.md has a new attempt section; if not, treat it as a failed attempt.

## 4. Review
Set state `REVIEW`. Then dispatch **in parallel** (one message):
1. `reviewer` with the ticket path and attempt number. **Small-diff review** (default `on`): when the diff
   (`git diff --shortstat origin/main...HEAD`) is under 100 changed lines and touches no High path, dispatch it with model
   `sonnet` (unless overridden). Review-trigger agents keep their own model or override.
2. Every agent in the **Review triggers** table of `loop.config.md` whose trigger matches: its `Areas` condition, **or** a changed path (`git diff --name-only origin/main...HEAD`) matching its path list. Append each reply to its output file (e.g. `security-review.md`, `a11y-review.md`) under `## Attempt N`.

Read the latest section of `review.md`. The verdict is the first line: `Verdict: PASS` or `Verdict: REWORK`. A 🔴 finding in any review-trigger output turns a PASS into REWORK: append it to the review attempt under "Blockers from review agents".

## 5. Loop decision
- **PASS** → set state `DONE` in ticket.md, commit `work/tickets/<ID>/` (`<ID>: done`). Go to 6.
- **REWORK** and reworks so far < 2 → increment `Attempts` in ticket.md, set state `REWORK`, dispatch `implementer` with "REWORK attempt N: fix only the issues in the latest review.md section (and the review-agent blockers listed there)", then return to step 4.
- **REWORK** and reworks so far = 2 → set state `ESCALATED`, write `work/tickets/<ID>/escalation.md` from `work/templates/escalation.md` (what failed each attempt, root-cause guess, options for Ming), add an item to `work/ming-todo.md`, go to **Stop and hand off**.

## 6. Open the pull request (DONE only)
1. Rebase on the latest main if it moved (`git fetch origin main && git rebase origin/main`). On conflicts in files outside `work/`, abort the rebase, keep the PR unrebased and list the conflict under *Needs Ming's decision*.
2. Push the branch: `git push -u origin <branch>`.
3. Open a PR into `main` (GitHub MCP `create_pull_request`, or `gh pr create`). If a PR for this branch is already open, update it instead of opening a second one.
   - Title: `<ID>: <ticket title>`.
   - Body (English, short):
     - **Summary**: what changed, 2–4 bullets.
     - **Acceptance criteria**: the ticket's checklist, each ticked with one line of evidence from `review.md`.
     - **Checks**: the results of the checks in `loop.config.md`, from the review.
     - **Needs Ming's decision**: divergences from the scope sources, planner assumptions to confirm, Ming steps after merge (or "none").
     - **Follow-ups**: from impl-log, review and review-agent files.
     - Links to `plan.md`, `review.md` and every review-agent file in the ticket folder.
     - End with the attribution line required by the session.
4. Write the PR URL into ticket.md (`| PR | <url> |`), clear `Claimed by`, append the Handoff entry (below), commit `<ID>: link PR`, and push.
5. **Never approve, merge or enable auto-merge.** Ming reviews and merges the PR.

## Stop and hand off (BLOCKED / ESCALATED)
Clear `Claimed by`, append the Handoff entry, commit `work/tickets/<ID>/` and `work/ming-todo.md` (`<ID>: plan blocked` / `<ID>: escalated`), push the branch (no PR), and stop: show Ming the questions or the escalation.

## Handoff entry
Append to `## Handoff` in ticket.md:
```
### YYYY-MM-DD — claude — <final state>
- Agent calls: <n>, tokens <total in/out> (<agent × count, model, tokens>; e.g. planner×1 sonnet 41k/3k, implementer×2 …)
- Done: …
- In progress / next: …
- Gotchas: …
```

## 6b. Update the board
On `main` (pull first), set the ticket's board row to its final state (`DONE` with attempts, `BLOCKED` or `ESCALATED`) and today's date; commit `chore: board — <ID> <state>` and push. Switch back to `main` before ending, with a clean tree.

## 7. Report to Ming
Short summary in Vietnamese: ticket, final state, attempts, files changed (`git diff --stat origin/main...HEAD`), check results, follow-ups the agents listed, and the next step: the PR link to approve and merge, or the escalation / blocking questions. Then name the next runnable ticket (or why none is).

## Guardrails
- Pass each subagent only what it needs (paths, attempt number, the exact instruction). Do not paste whole files into prompts.
- Never edit `plan.md`, `impl-log.md`, `review.md` or a review-agent file to change an outcome.
- If a subagent fails or returns nothing twice in a row, set `ESCALATED` with the reason and stop.
- Never read `.env*` values. Everything under **Guardrails** in `loop.config.md` applies too.
